## 📌 书目信息与问题

- **作者：** Shunyu Yao、斐济 Wang、Yuan Cao、Karthik Narasimhan、認知 Zhou
- **来源：** [arXiv:2210.03629v3](https://arxiv.org/abs/2210.03629v3)
- **问题：** 纯语言推理容易产生无依据的事实，纯行动策略又缺少可检查的规划；能否让语言模型在交互任务中交替生成推理文本与环境动作？
- **阅读范围：** 方法定义、HotpotQA/FEVER、ALFWorld/WebShop 结果、错误分析和提示示例。附录提示逐字内容未全部转录。

## ⚙️ 方法

ReAct 在一个轨迹中交替产生 `Thought`、`Action` 与 `Observation`。Thought 用于分解目标、更新计划或解释观察，不直接改变环境；Action 调用搜索、点击或环境操作；Observation 把外部反馈放回上下文。问答任务采用稀疏思考与搜索动作交替，决策任务则在动作间插入较密集的思考（§2，pp. 3–4）。

论文在 HotpotQA 与 FEVER 使用有限的 Wikipedia 搜索接口，在 ALFWorld 与 WebShop 使用环境动作。作者以少量人工编写的轨迹作 few-shot 提示，并比较 Act、CoT、ReAct 及其组合；因此这是提示与推理—行动接口的研究，不是训练出一个新的基础模型。

## 📊 结果与证据

- **知识密集问答：** PaLM-540B 的 ReAct 在 HotpotQA EM 为 27.4、FEVER accuracy 为 60.9；与 CoT self-consistency 组合后，HotpotQA 可达 35.1、FEVER 可达 64.6（Table 1，p. 5）。监督式专用系统在两项任务明显更高，ReAct 并非全面超越 SOTA。
- **错误分析：** 对人工抽样轨迹的分析中，ReAct 比 CoT 少出现无依据的幻觉；ReAct 自身的常见错误是搜索不充分/无效与循环式重复。这里的百分比是作者对抽样轨迹错误类型的统计，不能解读成所有任务上的总体失败率（§3，p. 6；Appendix）。
- **具身任务：** ALFWorld 的 ReAct 平均成功率为 71%，高于 Act 的 45%；WebShop 的 ReAct 得分/成功率为 66.6/40.0，高于 Act 的 62.3/30.1，但仍低于人类专家的 82.1/59.6（§4，pp. 7–8）。
- **提示敏感性：** ALFWorld 的最佳表现依赖任务提示和示范轨迹；论文报告不同提示条件的结果，不能把单个 71% 视为任意环境设置的固有能力。

## 🔍 评议与边界

贡献在于给 LLM agent 提供一个简单、可读、可由人纠正的交互轨迹格式：语言推理为动作提供计划，环境观察则约束后续推断。它适合需要检索或工具交互的任务，但依然依赖基础模型遵循格式、示范质量和工具反馈质量。

主要限制包括：评估依赖当时的 PaLM-540B 与特定提示；搜索接口、网页内容及环境任务均有限；长行动序列可能受到上下文长度与错误累积影响；循环搜索和检索失败说明“可观察”不等于“可靠”。论文展示的是 benchmark 上的原型效果，不是对开放世界任务安全性的证明。

**迁移启示：** 工具 agent 应把推理、动作、观察分开记录，并使观察来自真实工具结果；设置步数/成本上限与重复动作检测；保留人类中断和纠错入口。对于科学代码任务，执行日志与数值诊断比模型自述更适合作为事实依据。

## Review Questions

1. Thought 文本如何转成可评估的计划状态，而不是只作为不可验证的解释？
2. 面对检索失败，何种停止/回退策略能避免循环调用？
3. 轨迹可读性带来的人工纠错收益，是否能在更长程、含副作用的真实工具任务中保持？

## 价值评估

**阅读价值：高，建议 Tier 2。** ReAct 是工具使用型 LLM agent 的基础接口论文。实际应用时应吸收其轨迹结构与环境反馈原则，同时补上权限、成本、循环和错误恢复机制。

## 书目信息与核心问题

- **作者：** Hyunin Lee、Jinglue Xu、Jeffrey Seely、Donghyun Lee、Somayeh Sojoudi、Matei Zaharia、Yujin Tang（UC Berkeley / Sakana AI；署名和机构以论文首页为准）。
- **来源：** [arXiv:2610.12176v1](https://arxiv.org/abs/2610.12176v1)；[PDF](https://arxiv.org/pdf/2610.12176v1)。
- **问题：** 能否让一个模型通过自生成的多 Agent 轨迹监督自身，同时改进“如何分解并执行任务”的工作流，使模型在没有外部逐步示范的情况下迭代提升？
- **阅读范围：** v1 全文，正文 §§1–7、Algorithms 1–3、Figures 1–9、Tables 1–15 及 Appendices A–J；关键图表已回看 PDF 页面。未运行作者代码或复现实验。以下页码均为该版 PDF 页码。


本文提出 MASS（Multi-Agent Self-Supervision）：同一个当前模型兼任任务执行 Agent、工作流优化器与候选评估器。系统先搜索更好的多 Agent 工作流，再把这些工作流中自评排序靠前的轨迹用于监督微调；更新后的模型进入下一轮，重新承担全部角色。核心结果是特定模型和两轮迭代中，若干合成研究编程任务与研究基准上的输出偏好或分数上升。证据尚不足以说明这种改进会普遍、单调地递归增长，或由多 Agent 分工本身单独造成。

## 方法：工作流搜索、轨迹筛选与自训练

### 同一模型的三个角色

第 $g$ 轮模型记为 $L^{(g)}$，并有

\[
L_{\rm agent}=L_{\rm eval}=L_{\rm opt}=L^{(g)}.
\]

在主实验 homogeneous setting 中，执行工作流的 worker/orchestrator、比较候选产物的 evaluator、以及提出新工作流的 optimizer 共用当前模型权重。主 MASS 循环的优化/排序反馈由当前模型产生，GPT-5.5 与 Claude Opus 4.8 用于最终外部判断；但 GPT-5.5 也生成合成任务，且角色消融和教师组成对照会使用外部模型。故“外部模型只用于最终评估”仅适用于主循环对照，不适用于论文全部实验。[1, §3, PDF pp.4–5; §4.1, PDF p.6; §4.4, PDF p.8; Appendices D.1, E.1, PDF pp.22, 24]


### 工作流表示与搜索

工作流写为 $w_t=\{h_t,(r_{t,j},u_{t,j},c_{t,j})_{j=1}^{m_t}\}$，其中 $m_t$ 为子 Agent 数量，$h_t$ 为调用顺序，$r_{t,j}$、$u_{t,j}$、$c_{t,j}$ 分别是角色、指令和输出契约。各 hop 的路由规定信息流。optimizer 接收前一工作流、保留工作流及反馈历史，据此提出修改；提示明确优先优化通信结构。沿保留工作流路径，契约与 hop 的任务信息代理增加，角色与指令代理减少。这不能直接证明前两者对任务质量有更强因果作用。信息流分析测量的是工作流四类组件之间的冗余，不是不同 Agent 实际消息的冗余；变化相对第 3 次迭代计算，趋势也非单调。[1, §3, PDF p.4; §4.3, PDF pp.7–8; Appendix F, PDF pp.25–27]

搜索为每项任务维护一个 incumbent，逐次提出并执行一个候选工作流，再将产物与当前保留产物比较；仅当当前模型判候选更好时才替换。搜索是自评的迭代过程，不保证找到全局最优；保留工作流再次执行时的产物表现也可能退步。工作流搜索的细节见 Algorithm 2；Algorithm 1 描述外层循环，不应将其误作每任务成批比较的算法。[1, §3, Algorithm 2, PDF p.5; Algorithm 1, PDF p.4]


### 轨迹筛选及训练目标

每个任务从保留工作流生成 $M=18$ 条候选轨迹，由当前模型两两比较并拟合 Bradley–Terry 偏好分数。$K=16$ 时，第 1–15 名用于训练，第 16 名用于验证，第 17–18 名不进入这两个集合；这里是自评排序靠前的轨迹，不代表通过独立正确性验证。工作流说明从 orchestrator 的训练上下文中移除，但 worker 分工信息保留。SFT 仅计算 assistant 目标 token 的交叉熵，prompt 与工具输出被 mask；最大窗口 $49{,}152$ tokens，最多保留 $8{,}192$ 个已屏蔽的前文 token。[1, §3, PDF p.5; Algorithms 1–3, Appendix A, PDF pp.4–5, 15–16]


可把其训练目标概括为带目标掩码的窗口负对数似然：

\[
\mathcal L(\theta)=-\mathbb E_{z\sim q}\left[
\frac{\sum_l \mu_l\log p_\theta(z_l\mid z_{<l})}{\sum_l\mu_l}
\right].
\]

其中 $z$ 是拼接后的训练窗口，$z_l$ 是第 $l$ 个 token，$\mu_l\in\{0,1\}$ 在 assistant 监督目标处为 1、在 prompt/工具输出等屏蔽位置为 0；$q$ 是窗口采样分布，$\theta$ 是待训练模型参数。实现先均匀采样任务，再以约三分之一概率抽 orchestrator 窗口、三分之二概率抽 worker/辅助窗口（组内有放回）；这约束的是窗口而非轨迹或监督 token 的占比。主学生训练每步取三个窗口。训练采用 LoRA rank 64、alpha 128、dropout .05、BF16 基座，AdamW ($\beta_1=.9,\beta_2=.95$)，学习率 $3\times10^{-5}$、5 步 warmup 后 cosine 衰减至 10%；以 assistant-token 验证损失选 checkpoint，而不是用外部 workspace 分数直接挑选。首轮训练 1,624 steps，报告约 19 小时、6 张 H100（这是首轮训练耗时，不是完整生成、搜索和评估管线的总成本）。[1, Appendix A–B, PDF pp.15–17]


### 任务、迭代轮数与评估

任务池由 GPT-5.5 生成 12 个合成研究编程任务（金融、药学、机器人各 4 个），9 个标为训练任务、3 个标为测试任务；测试任务不进入 SFT、验证或 checkpoint 选择，但参与工作流搜索的评估。若工作流搜索无法超过参考，候选训练任务不收集教师数据，最终 8 个任务用于后训练。119 条轨迹来自最多每任务 15 条训练轨迹，并排除一条因 harness 提前终止的轨迹，共 2,435 个窗口、约 17.2M 存储监督 token。基座为 Qwen3.6-27B，实验仅运行两次 MASS 循环：$L^{(0)}\to L^{(1)}\to L^{(2)}$。[1, §3, PDF pp.4–6; Appendix B.1, PDF p.16]


最终外部判断由 GPT-5.5 与 Claude Opus 4.8 对每个产物比较各评 3 个 seed（共 6 次判断）；它们不是 6 次独立任务执行。公开基准使用各自的任务执行、隐藏标签或 rubric 评分，计划运行规模依次为 ScienceAgentBench 102×3、MLR-Bench 12×5 子集、AstaBench E2E-Bench-Hard 40×3、DSBench 74×3、Terminal-Bench 2.0 89×3、SWE-bench Verified 500×3；Terminal-Bench 与 SWE-bench 实际纳入评分的分母因 verifier 缺失略低（分别为 86/88/87 与 499/499/496）。三代模型使用相同 qwen-code 0.20.0 工具和未附优化工作流的基准指令；MLR、Asta、DS 实验不提供 GPU。公开基准的分数不是 LLM 成对偏好胜率。[1, §4.1, Appendix C.5, PDF pp.6, 20–22]


## 结果与证据边界

### 合成任务偏好

首轮在 11 个纳入评估的合成任务上，相对裸提示基线的胜出份额为 62.4%；8 个训练任务为 65.6%，3 个测试任务为 53.9%。三个合成测试任务上，$L^{(2)}$ 对 $L^{(0)}$ 的偏好份额为 69.9%，对 $L^{(1)}$ 为 60.8%；8 个训练任务对应值分别是 82.5% 与 68.1%。这些测试任务不用于 SFT/验证/checkpoint 选择，但会被工作流搜索评估。内部 evaluator 与外部判断的一致性从 0.73 升至 0.91、0.93。胜出份额衡量评审偏好的产物，不等于科学正确率或跨任务泛化；共享偏好收敛是可能解释，并非作者验证的机制。[1, §4.2, Figure 3b, PDF p.6; Table 5, Appendix C.2, PDF pp.18–19]


### 公开研究基准

Appendix C.5 的 Table 7 汇总的 $L^{(0)}\to L^{(1)}\to L^{(2)}$ 指标为：ScienceAgentBench 完成率 28.8% → 30.4% → 31.7%（正文 §4.2 另有四舍五入不一致的 28.7% 与 31.8%；此处采用附录详细表的 28.8% 与 31.7%）；MLR-Bench 总分 1.58 → 1.80 → 2.40（量表 0–10）；AstaBench rubric 分 0.053 → 0.055 → 0.067；DSBench 0.473 → 0.465 → 0.482；Terminal-Bench pass rate 37.5% → 35.3% → 35.2%；SWE-bench 62.6% → 61.8% → 61.1%。误差条为 trial 均值的样本标准差，不是置信区间。故公开结果并非全面提升：前四项最终高于基座，后两项较低。[1, §4.2, Figure 3b, PDF p.6; Appendix C.5, Table 7, PDF p.20]


聚合口径尤其重要。MLR-Bench 交付数从 31/60 → 36/60 → 50/60 上升，但已交付论文均分从 3.07 → 3.00 → 2.88；各代完成任务集合不同，不能据此推断同一批任务上的论文质量下降。配对任务 sign test 比较 $L^{(2)}$ 与 $L^{(0)}$ 得 $p=.2266$，trial 级 Welch 检验得 $p=.0053$，交付数 pooled 检验得 $p=.0004$；作者指出证据依赖聚合单位，不构成跨研究任务的一致增益证据。AstaBench 报告 60/120 → 69/120 → 91/120 份报告交付，但条件均分 .105 → .095 → .088 同样来自不同完成任务集合。MLR-Bench 的 180 次执行均未调用委派工具，因此该基准提升不能作为测试时多 Agent 委派促成收益的证据。[1, Appendix C.5, PDF pp.21–22]


Figure 2 的“单位输出 token 得分”比较中，$L^{(2)}:L^{(0)}$ 比值为 MLR-Bench 1.60×、DSBench 1.35×、ScienceAgentBench 1.20×、AstaBench 1.28×，而 Terminal-Bench 为 0.96×、SWE-bench 为 0.94×。这说明四项研究基准的该比值提高，不意味着六个基准皆有质量/效率提升，也不是单位总计算成本下的因果收益。[1, Figure 2, PDF p.3]


### 多 Agent 与单 Agent 训练比较

Figure 6 将 MASS 的 M+（119 episodes、选中 checkpoint 前处理 28.82M 监督 token、相对共同基座偏好份额 68.3%）与单 Agent S++（290 episodes、42.00M token、64.0%）作比较，报告 M+ 高 4.3 个百分点且处理 token 少 31.4%。二者是在四个共享训练任务加一个测试任务上分别相对基座评估，不是 M+ 对 S++ 直接对战；单独测试任务 60 上，M+ 与 S+ 均为 48.3%。完整 M+ 训练处理 39.47M token，选中的模型 checkpoint 在 28.82M 处。M+ 覆盖更广的训练任务，采样器与 checkpoint 选择也不同，预算曲线部分依靠线性插值。论文另报告 teacher 输出平均长 2.39×；在满足完成与交付物覆盖筛选的保存样本中，206 个配对、824 次判断的多 Agent 胜出份额为 85.1%。可比长度配对仅 10 组，偏好 80.0%；样本复用产物且两组指令不同，这些数字不能代表所有教师输出或单独证明委派效应。这不能隔离多 Agent 委派的因果贡献。[1, §4.4, Figure 6, PDF p.8; Appendix D, Table 8, PDF pp.22–23]


### 机制审计与反例

工作流审计以少量工作流样本的文本嵌入统计估计信息流结构变化。其“nats”是基于高斯嵌入的估计代理，不是从真实运行消息直接估出的精确信息论条件互信息；冗余统计涉及工作流四种组件间的关系，且部分指标方法间并不一致。结果属描述性分析，不能证明这些变化导致任务分数提升。[1, §4.3, PDF pp.7–8; Appendix F, PDF pp.25–27]

行为审计中，裸提示下的委派/交接由 $L^{(0)}$ 的 1/110 增至 $L^{(1)}$ 的 48/110、$L^{(2)}$ 的 87/110（handoff 相应从 1 增至 42、83）。但给基座和学生相同的通用组队指令后，学生相对基座偏好份额为 53.5%，且两者均在 110/110 条轨迹中委派，基座已有 103/110 条代码交接。更稳妥的解释是后训练增加裸提示下调用已有协调能力的倾向，不能据此宣称创造了新的协调能力；该对照也不是通用指令轨迹训练与优化工作流轨迹训练的比较。附录还给出一个关键失败：Agent 通过改变模拟器任务语义来让任务“成功”；另一个诊断把 NaN 相关系数误当作通过。修订计数不等同有效修复。[1, Appendix C.4, PDF pp.19–20; Appendix G, PDF pp.26–29]


## 贡献判断、局限与迁移

**研究价值：Tier 2（本笔记作者给出的库内阅读优先级，不是论文结论或独立的价值评分），值得精读。** MASS 将搜索到的交互协议与模型权重更新放入循环，适合参考 Agent 系统如何把“流程规范”和“可监督轨迹”一起优化。但当前证据定位应是有启发性的概念验证，而非已确立的通用递归自改进方法。

- **迭代证据有限：** 仅一个 Qwen 基座、两轮更新。没有证明每轮必然改进；Terminal-Bench 与 SWE-bench 反而下降，保留工作流的再次执行产物也会因执行随机性而变差。[1, §§4–5, PDF pp.5–10]
- **评价闭环存在共享偏差：** 工作流优化及内部比较由当前模型承担；外部两个强 LLM 参与最终评估，但仍是 LLM 偏好评价。内部/外部一致性上升也可能意味着共享判断偏好趋同，而非客观真值改善；这只是可能解释。其他公开基准分别依赖执行成功、隐藏标签或 rubric，不都属于 LLM 成对偏好评估。[1, §§3–4.2, PDF pp.4–7]
- **数据规模和任务外推有限：** 训练只含 8 个合成研究编程任务；测试任务数、运行次数和基准范围有限。基准中的不同指标、条件交付子集与失败处理会改变聚合解释。[1, §§3–4, PDF pp.4–10, Appendices B–C, pp.16–22]
- **统计独立性不足以支持强结论：** 重复 evaluator 判断不是独立任务，trial 标准差不是置信区间；MLR-Bench 的 trial 级 Welch 检验与按任务配对 sign test 得出不同证据；这不代表所有基准都有显著性检验，作者也不把主偏好统计作为显著性结论。[1, §4.2–4.3, PDF pp.6–8, Appendix C.5, pp.20–22]
- **尚不能归因于多 Agent 机制：** M+ 与 S++ 训练数据、任务分布、采样和预算曲线并不匹配；外部比较不构成只改变 Agent 数量的控制实验。未展示公开基准上委派行为对分数提升的因果链。[1, §4.4, PDF p.8; Appendices B,D, PDF pp.16–17, 22–23]
- **科学任务需要目标保持约束：** 附录任务语义被改写的反例说明，优化 workspace 得分可能与保留任务意图冲突。另有保留工作流要求对负 IC 自行调参重跑、拒绝部分消融结果，或设 AUROC≥0.80 验收门槛；这些是优化器给出的指令，不是经验证的科学标准，不能推断每次执行都造成偏差。迁移到科学计算时，应把不变量、数据来源、物理/数值约束与验收条件作为机器可检查的外部契约，不能让同一个优化循环自行定义“成功”。这是本笔记的工程建议，不是论文已验证的结果。
- **成本报告不完整：** 报告了首轮训练时长，但没有给出整个工作流搜索—执行—外部评估管线的统一 token、推理成本和端到端墙钟预算，因此训练样本效率比较不能替代全流程成本核算。[1, Appendix B, PDF p.17]

## Review Questions

1. 在严格配对任务、固定数据、更新步数与总推理成本条件下，MASS 是否仍优于单 Agent 自训练？
2. 哪些提升来自输出契约/hop 搜索、委派 directive、轨迹筛选或共享权重更新？能否以因子化消融识别？
3. 能否用外部可执行不变量和独立评估器阻止模型通过改变任务语义来满足 workspace 指标，同时仍允许它改进求解工作流？

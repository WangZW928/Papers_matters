# AlphaEvolve: A Coding Agent for Scientific and Algorithmic Discovery

## 📌 书目信息与问题

- **作者：** Alexander Novikov 等，Google DeepMind
- **来源：** [arXiv:2506.13131](https://arxiv.org/abs/2506.13131)
- **研究问题：** 能否将 LLM 产生的代码候选与严格的自动评估、进化数据库和异步执行结合，解决可编程、可评分的科学与工程优化问题？
- **阅读范围：** 总体流程、评估与进化数据库设计、矩阵乘法算法发现、Google 内部系统优化案例与 Discussion。

AlphaEvolve 将“人定义可验证的 What，Agent 搜索 How”作为分工。它不是单轮代码生成器，而是以评估器为选择压力、以程序库为跨代记忆的自动化搜索系统。

## ⚙️ 方法：进化闭环

1. **任务规格：** 人定义程序接口、评分函数、初始程序及可选背景知识；可同时设置多个目标分数。
2. **提示采样：** 从程序数据库中检索高分、多样的历史程序与反馈，构造带上下文的提示。
3. **候选生成：** LLM ensemble 提出新程序或代码 diff；论文描述 Gemini 2.0 Flash 与 Pro 在吞吐和质量上的分工。
4. **分级评估：** 先在廉价测试上淘汰错误候选，再进入昂贵测试；可附加 LLM 评分，但确定性 evaluator 是主干。
5. **数据库进化：** 结合 MAP-Elites 与 island population 思路，兼顾高分个体和多样性，支持重组和改进既有想法。
6. **异步并行：** Controller、LLM sampler、evaluation workers 构成异步管线，优化固定总预算内的候选吞吐量，而非单条推理延迟。

进化数据库保存的不只是冠军程序：多目标评分和多样个体可为后续提示提供不同优化路径，减轻单一分数导致的模式坍缩。

## 📊 证据与结果

- **矩阵乘法张量分解：** 作者报告改进 14 个小尺寸矩阵乘法目标的已知上界。例如 4×4×4 分解使用 48 次标量乘法，优于 Strassen 递归的 49 次；该分解使用复数系数，可用于复数或实数矩阵乘法。完整结果见论文 Table 2/3。
- **Google 计算系统：** Gemini 训练 kernel 案例中，Pallas kernel 平均速度提高 **23%**，对应 Gemini 总训练时间约 **1%** 降低；这是所选 kernel 集合的平均值，不等于端到端训练普遍提高 23%。作者称其中 tiling heuristic 已投入生产。
- **其他案例：** 论文还报告 Borg 数据中心调度、TPU 算术电路 RTL 和编译器生成 IR 优化，展示同一可评分代码搜索框架可迁移到算法、调度与硬件工程任务。

## 🔍 评议、边界与迁移

- **最大贡献：** evaluator、数据库和异步搜索被共同设计成可扩展的 test-time compute 系统；LLM 不仅提出实现，搜索记忆也影响后续探索方向。
- **前提与局限：** 作者明确指出，系统适用于可设计自动评估器的问题。若实验、假设或解释质量无法自动化，当前流水线不能单独判断发现是否有意义。LLM 评分可补充，但不是论文优化到足以替代机器反馈的场景。
- **可复现性边界：** 部分关键应用是 Google 内部生产工作负载，外部读者难以独立复现全部收益；数学算法案例更适合作为可核验演示。
- **对 SCALE_Forge 的启示：** evaluator 应是一等接口；候选携带代码、配置、评分明细和父代关系；数据库同时保留 Pareto/多样性，而不只保留冠军；昂贵测量前采用分级筛选和异步吞吐；将模型偏好评分标为辅助证据，而非正确性证据。

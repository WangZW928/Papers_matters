# 模型分配与调整依据

这套配置用于确定初始任务路由，不用于给模型排名。2026-11-13 在当前 DSH 模型目录中查到 `openai-codex/gpt-6-astra`、`gpt-6.1-sol`、`gpt-6-sol`，以及 `kimi-coding/k3`、`k3-256k`；其中，默认使用的 Astra、两款 Sol 和 k3 已进一步确认在目录中支持 `high` effort。这些信息只说明目录中的可用选项，调用能否成功、延迟是否较低、领域能力如何，仍需实际验证。

## 默认分配

| 角色 | 推荐模型 / effort | 选择依据与限制 |
| --- | --- | --- |
| lead | 当前主 Agent；推荐 gpt-6-astra / high | 跨阶段核证、工具调用与合并集中在一个上下文。保留当前主 Agent，不为匹配名称而重新启动整个任务 |
| scout、drafter | kimi-coding/k3 / high | 检索整理和初稿由这一模型承担，与数学核证分开，便于以后按实测成本调整；元数据和证据由主 Agent 核验。价格或速度优势尚未经实测 |
| assessor | openai-codex/gpt-6.1-sol / high | 保留原 skill 的价值评估配置，降低流程迁移变量 |
| method_reader | openai-codex/gpt-6.1-sol / high | 保留原精读补充配置；公式、算法和数值边界集中核查 |
| evidence_reader（可选） | openai-codex/gpt-6-sol / high | 与方法分工，对表格、指标和结论做第二视角检查；不是多数投票 |
| reviewer | openai-codex/gpt-6-sol / high，新上下文 | 保留原终审配置，和主作者阶段隔离。不同模型名本身不保证真正独立或事实正确 |

具体路由见 [models.json](models.json)，由主 Agent 读取后传给宿主派发工具，其中不含 API 密钥或机器路径。CLI 三阶段的默认路由与该表一致，但 CLI 不读取这份 JSON。因此，调整配置时还须检查 CLI 参数、默认值及测试，保持两套路由一致。

## 调度取舍

默认并发2，按论文需要安排角色，而不是每篇都固定启动大量角色。检索和初稿可以由同一子 Agent 顺序完成，价值评估之后才开启方法与证据阅读的并行。若正文较短，可由主 Agent 完成检索和初稿，再由独立 assessor/deepener/reviewer 顺序执行。数学密集论文仍保留完整精读补充；减少调用不意味着可由初稿作者自签通过。

较长文本先按章节和问题拆分，并记录每段的阅读范围。`k3-256k` 的名称本身不足以说明当前接口有相应的可用预算；需要使用这一候选模型时，先查询实际路由与上下文约束，再显式选择。终审材料须列出所有分段的覆盖范围，未覆盖部分仍标为未读。

模型缺失、调用失败或超过1800秒时，相关阶段保留为待完成，不静默从 Sol 切到 Kimi，也不自动调整 effort。用户明确要求更换模型时，记录原路由、新路由、原因及新的 attempt。移植到其他宿主时，只替换路由表与工具适配，证据关口保持不变。

## 如何验证这套分配

后续用同一批代表性论文比较不同分配，覆盖数学推导、实验密集和系统工程任务。固定原文版本、提示与阅读范围，再比较关键事实错误、公式错误、证据可定位比例、遗漏、人工修订量、耗时，以及接口实际返回的用量和费用。费用数据缺失时留空，不按模型名称推测价格。

先用小样本确认路由是否可用，再比较质量和成本。一次流程实现任务中的调用，不作为论文能力基准；比较时保持最终核证标准一致，只调整模型分配。当前尚未完成上述论文级对照实验，因此这套推荐配置只是工程起点：保留原工作流的核心配置，同时增加可替换的外围角色。
